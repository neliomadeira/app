# Pages & markup

## The page skeleton

Every page is the same document with a different middle. Copy `agenda.html` and replace
the hero and `<main>`; don't assemble a page from scratch.

```
<!DOCTYPE html> / <html lang="pt-PT">
<head>
  charset
  inline theme script          ← must stay here, before any stylesheet
  viewport, title, description
  og: + twitter: meta          ← title/description duplicated across three places
  logo preload
  css/styles.css
  Google Fonts (preconnect → preload → print-media swap → noscript)
  theme-color, manifest, icons
  canonical                    ← absolute https://www.jscampinense.pt/<page>.html
</head>
<body>
  <a href="#main-content" class="skip-link">Saltar para o conteúdo</a>
  <header class="header" id="header"> … identical on every page … </header>
  <section id="main-content" class="page-hero page-hero--dark"> … </section>
  <main class="container"> … the page … </main>
  <footer class="footer"> … identical on every page … </footer>
  <script defer> × 10-13, in a fixed order
</body>
```

### The inline theme script

```html
<script>try{document.documentElement.setAttribute("data-theme",localStorage.getItem("jsc_theme")||"light")}catch(e){}</script>
```

It is deliberately the second thing in `<head>`, inline and unminified. It runs before
the stylesheet is parsed so a dark-mode visitor never sees a white flash. Moving it after
`<link rel="stylesheet">`, deferring it, or extracting it to a file all reintroduce the
flash. The `try/catch` matters: Safari in private mode throws on `localStorage`.

### Hero variants

- `page-hero page-hero--dark` — interior pages, solid dark band under the fixed header.
- `.hero` — homepage only. Its presence switches `js/nav.js` into scroll-aware mode
  (`header--transparent` at the top, `header--scrolled` after 80px). A page with a
  `.hero` element but no full-bleed image gets a transparent header over white text.

## Adding a new page

Five registrations, and the site half-works if you do only the first.

1. **The file** — copy `agenda.html`, update title/description/og/twitter/canonical
   (the same sentence appears in six meta tags; change all six).
2. **The nav** — the `<nav>` block is duplicated in every HTML file. Adding a link means
   editing all of them, including `404.html`, `offline.html` and `manutencao.html`.
3. **`sitemap.xml`** — add a `<url>` entry.
4. **`sw.js`** — add the page and its module to `PRECACHE`, and bump `CACHE_NAME`
   (`jsc-v14` → `jsc-v15`). Without the bump, returning visitors keep the old cache and
   never see the page; without the PRECACHE entry it's unavailable offline.
5. **The footer** — add to `footer__links` if it belongs in a quick-links column.

## Nav conventions

**Incorrect** — literal emoji and a bare active style:

```html
<li><a href="galeria.html" class="nav__sublink">📷 Galeria</a></li>
```

**Correct** — HTML entity, matching the rest of the menu:

```html
<li><a href="galeria.html" class="nav__sublink">&#128247; Galeria</a></li>
```

The entity form survives the FTP editors and CMS pastes these files pass through; a raw
emoji has repeatedly come back mojibaked.

Active state is applied by `js/nav.js` from `window.location.pathname` — it adds
`nav__sublink--active` and `nav__link--active`. Don't hand-write an active class into the
markup; it will be wrong on every other page that shares the block.

The inline `style="color:var(--yellow)"` you'll see on some nav items is a per-page
highlight and predates the automatic active state. Leave existing ones alone, but don't
add new ones — let `nav.js` do it.

## Accessibility baseline

The site already meets these; keep them.

- Skip link first in `<body>`, targeting `id="main-content"`.
- Dropdown toggles are `<button>` with `aria-haspopup` and `aria-expanded`.
- Icon-only links carry `aria-label` **and** `title` (`nav__search-btn`, social links).
- Decorative skeletons are `aria-hidden="true"`.
- Images have `alt`, explicit `width`/`height` (prevents layout shift), and `loading="lazy"`
  below the fold. The logo is the exception: `fetchpriority="high"`, no lazy.

## Skeletons

Loading placeholders are written in the HTML, not generated by JS, so they paint on first
frame while the module is still parsing:

```html
<div class="agenda-card--skel" aria-hidden="true">
  <div class="skel-date skeleton"></div>
  <div class="skel-info">
    <div class="skel-line skeleton"></div>
    <div class="skel-line skel-line--sm skeleton"></div>
  </div>
</div>
```

The module replaces the container's `innerHTML` wholesale, which clears them. Three
repeats is the house pattern.
